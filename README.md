# Лабораторная работа № 4

**Создание приложений Windows с использованием средств прикладного программирования Win32 API**

Приложение Windows Forms на C#. Все операции выполняются прямыми вызовами функций Win32 API
(`kernel32.dll`, `user32.dll`) через Platform Invoke (`[DllImport]`). Обёртки высокого уровня .NET
(`System.IO.File`, `Clipboard` и т.п.) для заданий не используются.

## Сборка и запуск

Требуется Windows и Visual Studio 2022 (рабочая нагрузка «Разработка классических приложений .NET»)
или .NET 8 SDK.

* Visual Studio: открыть `Lab4.sln` → F5.
* Командная строка:
  ```
  dotnet run --project Lab4
  ```

Пункты 10–12 (метка тома) требуют прав администратора, если метка меняется на системном диске.
Программа сама предложит перезапуститься от имени администратора (меню «Файл»). Удобнее
выполнять эти пункты на флешке: её можно выбрать в списке «Диск».

## 4.2.1. Файловые операции

Каталожная структура создаётся в текущем каталоге программы:

```
TESTDIR\
└── S1\          ← текущий каталог после п.1
    ├── S2\
    │   └── S4\
    └── S3\
        └── S5\
```

Если в лабораторной работе № 3 структура была другой, достаточно поправить массив `SubDirs`
в начале файла `MainForm.Files.cs`.

| П. | Действие | Функции Win32 API |
|---|---|---|
| 1 | Создание структуры, вывод на экран | `CreateDirectory`, `SetCurrentDirectory`, `FindFirstFile`/`FindNextFile` |
| 2 | Создание `file1.txt`, запись «Текстовая строка» | `OpenFile(OF_CREATE)`, `_lwrite`, `_lclose` |
| 3 | Чтение файла целиком | `_lopen`, `_llseek`, `_lread` |
| 4 | 8 байт с 5-го байта | `_llseek(h, 4, FILE_BEGIN)`, `_lread` |
| 5 | Добавление «Дополнительная строка» | `ReadFile`, `SetFilePointer(FILE_END)`, `LockFile`, `_lwrite`, `UnlockFile` (+ проверка блокировки через второй дескриптор) |
| 6 | Атрибуты «только чтение» + «скрытый», попытка удаления | `SetFileAttributes`, `DeleteFile` → «Отказано в доступе» |
| 7 | Снять «скрытый», изменить дату создания | `SetFileAttributes`, `CreateFile`, `SystemTimeToFileTime`, `LocalFileTimeToFileTime`, `SetFileTime` |
| 8 | Переименование в `file2.txt` | `MoveFile` |
| 9 | Пересылка в S2, копирование в S3, вывод S1–S3 | `MoveFile`, `CopyFile`, `FindFirstFile` |
| 10 | Метка тома `LABEL` | `SetVolumeLabel` |
| 11 | Поиск метки и сравнение | `GetVolumeInformation` |
| 12 | Изменение/удаление метки средствами ОС (утилита `LABEL` или Проводник) и повторная проверка | `GetVolumeInformation` |

Дополнительно: «Выполнить п.1–9 подряд», «Удалить созданную структуру», «Очистить протокол».

## 4.2.2. Работа с памятью

1. **GetSystemInfo** — вывод по шаблонам строк из методички (`SProc`, `SPageSize`, `SMinAddr`, …).
2. **GlobalMemoryStatus** (+ `GlobalMemoryStatusEx` для объёмов > 4 ГБ).
3. **VirtualQuery** — адрес `lpAddress` выбирается по результатам п.1 и п.2
   (`lpMinimumApplicationAddress`, `Min + dwAllocationGranularity`, `lpMaximumApplicationAddress`,
   `Min + TotalVirtual/2`), а также адрес образа программы, `kernel32.dll`, переменной в стеке,
   блока в куче или вводится вручную. Кнопка «Карта адресного пространства» обходит всё
   адресное пространство процесса и сверяет суммарный объём свободных регионов с `ullAvailVirtual`.

## 4.2.3. Буфер обмена

Реализован пример из п.4.1: таймер, `CountClipboardFormats`, `OpenClipboard`,
`EnumClipboardFormats`, `GetClipboardFormatName`, `CloseClipboard`. Предопределённые форматы
выводятся с пометкой «(Предопределенный)», зарегистрированные — по имени.
Также можно поместить текст в буфер (`EmptyClipboard`, `GlobalAlloc`, `SetClipboardData`),
в том числе в собственном формате (`RegisterClipboardFormat`), и прочитать его в форматах
`CF_UNICODETEXT`/`CF_TEXT`/`CF_OEMTEXT` (`GetClipboardData`). Так видно автоматическое
преобразование форматов.

## Дополнительные условия

* **Заставка** — `SplashForm` (закрывается сама или по щелчку).
* **Меню с командами** — «Файл», «Файловые операции», «Память», «Буфер обмена», «Справка».
* **Справочная система** — F1 / «Справка → Содержание»: описание всех пунктов, особых ситуаций
  и ответы на контрольные вопросы.
* **Информационные сообщения и особые ситуации** — результат каждого вызова API проверяется;
  при ошибке выводится код `GetLastError` с системным текстом (уже существующий каталог,
  отказ в доступе, нарушение блокировки, отсутствие носителя, несовпадение метки и т.д.).
